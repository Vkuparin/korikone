# Retailer candidate evidence and bounded search

F15.8, 10 October 2026. This contract normalizes catalogue reads and supplies bounded miss searches. F15.2 still owns category suitability/ranking under the accepted [category policy](category-policy.md). No live retailer or AI requests were used.

## Actual data contract

`Product` in `src/domain/model.ts` retains its existing ID/provider/store/ingredient, pack amount/unit, usable price, stock, deposit, native unit/increment and observation time. Optional `evidence` and `cataloguePricing` survive real quote persistence through `src/application/quotes.ts`. Old quotes and demo/custom providers can omit them; absence remains unknown. They are quote data, not preferences or AppState/backup fields.

`src/domain/product-evidence.ts` exports `productEvidenceSchema` / `ProductEvidence`, `productFamilySchema` / `ProductFamily` and `cataloguePricingSchema` / `CataloguePricing`. Evidence contains:

- `source: "retailer-name"`, exact `quote` of the returned product name, recognized `category` or null, recognized `family` or null and bounded `{kind,value}` qualifiers. No request provenance or model-generated evidence enters this object.
- Optional source category/labels are represented by required `retailerCategory: string | null` and `labels: string[]`. They are retained as retailer data; arbitrary taxonomy names or packaging codes do not certify dietary attributes.
- Name recognition handles supported Finnish compounds/spacing, with Unicode letter boundaries. Families distinguish ordinary foods from plant/flavoured milk, crispbread/tortilla/sweet bread, egg products/other eggs, plant mince, garlic, prepared rice, plant cream, coffee forms/capsules/drinks, seasoning, prepared food, equipment and other foods. A missing family or qualifier is unknown; absence of a word is not a negative dietary claim.

`retailerEvidence(name, retailerCategory = null, labels = [])` in `src/stores/candidates.ts` creates these facts from recognized label phrases. Category-specific qualifier values reuse F15.7; duplicate/inapplicable qualifier kinds are invalid. Generic names cannot establish an unmentioned meat, rice, coffee or cream type. The exact source name remains available for review. This finite recognizer does not certify allergens, infer complete ingredients or cover arbitrary product names.

`CataloguePricing` contains source `amount` and `deposit` in integer cents or null, source `unit`/`basis` strings or null and `approximate: boolean | null`. Unsupported weighed prices remain readable here while `Product.price` stays null. Missing native units become `"unknown"`; unsupported/missing increments are zero. F4.1/F4.2/F4.3 must establish arithmetic and accepted write/readback units before using these values to price or transfer weighed goods. Existing domain `deposit` remains zero when no deposit is reported; the separate source field retains null rather than claiming a verified deposit value.

## Search API and limits

`candidateQueries(requirement)` preserves the original query, then supplies up to two fixed category aliases. It derives the category from existing classification or recognized request-name hints; it never rewrites the requirement, inferred provenance or unit. Case/whitespace/NFC-equivalent queries are deduplicated. Unsupported categories get the original query only.

`searchCandidates(provider, context, requirement, options?)` snapshots context and requirement, performs sequential reads and merges returned products by verified ID. The latest returned fields for a repeated ID win. An ID cannot change provider/store/ingredient binding. Returned products keep their actual units; a broad alias cannot turn a gram product into millilitres. Every alias still requires matcher validation.

Exports: `MAX_SEARCH_QUERIES = 3`, `MAX_SEARCH_RESULTS = 20`, `MAX_CANDIDATES = 60`, all per requirement. No pagination, recursion, model-generated queries or retry after an error. An original useful hit sends no alias. A miss means the supplied `isHit(product)` predicate found no usable result; the default checks known availability/price/pack/unit and existing name relevance. `Service.price` supplies its actual exclusions, accepted IDs, live relevance and confirmed-pack rules so excluded candidates or already confirmed packs do not cause an incorrect hit/miss. Matching policy is otherwise unchanged in this card.

`CandidateSearchOptions` has optional `isHit` and `signal`. Cancellation rejects a pending read promptly, discards late output and prevents subsequent aliases; existing provider transports may finish their already dispatched read. The coordinator must supply its operation signal and timeout and enforce the whole-operation requirement/search/concurrency bounds in F16.9. This module's per-row limit is not a whole-operation bound or a claim that the retailer request itself can be aborted.
