# 0.9.0: Receipt learning and purchases

Canonical task list. Read [the roadmap](../roadmap.md) and [AGENTS.md](../../AGENTS.md), then load only the assigned card and its dependencies. Existing IDs and status evidence are preserved.

Retargeted on 10 October 2026 after the owner selected design and Settings first for v0.6.0. This is a planned release target, not a shipping promise.

F18 extends F6/F7 and F15 rather than creating another history or preference store. A verified transfer is not a completed purchase. Repeat behavior uses real quote refresh and retains U10 approval.

Receipt-learning scope added on 10 October 2026: [design and privacy contract](../receipt-learning.md). Local purchase facts/accounting come first, optional semantic enrichment follows. Shared provider contracts land in v0.7.0; no local runner is shipped here. Original owner receipts stay in ignored `scratch/receipts/`; fixtures are sanitized and independently authored. All new cards are Planned, not implementation claims. Strong agents publish exact symbols/files before Simple handoff.
